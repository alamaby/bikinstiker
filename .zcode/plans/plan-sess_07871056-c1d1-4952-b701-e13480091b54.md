# Analisa + Plan: Migrasi Supabase Legacy Keys → sb_publishable / sb_secret

## Analisa Dampak (hasil riset dokumen resmi + inventaris repo)

### Pemetaan & timeline
- `sb_publishable_...` menggantikan `anon` (hak rendah, RLS tetap berlaku); `sb_secret_...` menggantikan `service_role` (BYPASSRLS). Keduanya **bukan JWT** — string opak yang divalidasi server-side. Kedua jenis key jalan berdampingan sampai legacy **di-disable manual** di Dashboard (reversible); deprecation target **akhir 2026**.
- Key baru tidak boleh di `Authorization: Bearer` (ditolak "Invalid JWT") — hanya header `apikey`. User access token tetap JWT (dipisah ke migrasi "JWT signing keys" — out of scope).
- **Tidak berubah**: RLS/policies, storage signed URL, auth.getUser(), verifikasi Ed25519 admob-ssv, alur bisnis.

### Dampak spesifik repo (inventaris lengkap)
1. **Flutter** (`supabase_client.dart:11`, `env_constants.dart`): `.env` var `SUPABASE_ANON_KEY` → nilai `sb_publishable_` (param `anonKey` SDK menerima string apa pun). Catatan: `.env.flutter` lokal owner **sudah** berisi sb_publishable — key sudah dibuat.
2. **10 Edge Functions**: pola seragam — anon+Authorization = client user-scoped (RLS), SERVICE_ROLE = admin DB/storage. Platform kini meng-inject `SUPABASE_SECRET_KEYS` & `SUPABASE_PUBLISHABLE_KEYS` (**plural, JSON object**: `JSON.parse(...)['default']`) **berdampingan** dengan legacy vars. Setelah legacy di-disable, legacy vars mati (issue #37648) → swap wajib sebelum itu.
3. **verify_jwt**: gateway hanya paham key legacy JWT. Selama legacy aktif, verifikasi user-JWT kita tetap jalan. Saat disable: flip `verify_jwt=false` + andalkan auth in-function (`auth.getUser()` sudah ada di 7 function; showcase-preview sudah false; admob-ssv & share-redirect memang public). **Ditemukan discrepancy**: admob-ssv & share-redirect (public) tidak punya entry `verify_jwt=false` di config.toml padahal migrasi 20260708000024 mendokumentasikan false — perlu diperbaiki.
4. **CI** (`ping-supabase.yml`): pakai service_role di apikey+Authorization — perlu fallback ke sb_secret + header apikey saja.
5. **Lokal** (`supabase start`): CLI masih legacy-only → helper **dual-read** wajib agar lokal tetap hidup.
6. Kontrak test env-name (surprise-me, showcase-preview, showcase-purchase-copy) men-assert nama var di source → ikut diupdate.

## Risks
- Nama env plural non-intuitif (`SUPABASE_SECRET_KEYS`) — ditangani helper + test.
- Setelah legacy di-disable, gateway verify_jwt bisa menolak (issue #41834) — mitigasi: checklist disable-day (flip false + deploy) dan sifat reversible.
- Local CLI tetap legacy → dual-read menjaga lokal; jangan hapus fallback sebelum CLI mendukung key baru.
- `.env` owner lokal memuat nilai campuran lama/baru — dual-read Flutter menoleransi keduanya.
